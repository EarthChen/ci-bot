# ADR-0001: class 2 修复语义定论（自动修测试，非转交）

## 状态

已决议（grilling 确认）

## 背景

SKILL.md 铁律 1 写 "发现失败根因在生产代码 → class 2/5 → 转交"，但同文件 G1 表与修复步骤写 "class 2 → 自动修 + 文档同步"。矛盾导致 agent 在 class-2 场景行为不确定，100031437 真实运行出现空 patch escalate。

## 决策

**class 2 = 被测代码行为变更导致测试过时 → agent 自动改测试 + 同步文档，不转交。**
**class 5 = 非单测失败（编译/依赖，生产真 bug）→ 转交人工。**

## 理由（权衡）

- class 2 的失败根因在被测代码"行为变"，但修复动作是"更新过时测试"，不触碰生产代码，符合 G3 边界（只改 `src/test/`/`docs/`）。
- 若 class 2 也转交，则测试过时场景 bot 永不自动修，与 "CI 单测自愈" 目标相悖，且会让 100031437 这类 case 永远 escalate。
- class 5 才是真正需要人工的工程决策（生产代码改动）。

## 影响

- 修改 SKILL.md 铁律 1，消除矛盾。
- agent 在 class-2 场景必须改测试并产出 patch，而非 escalate。
