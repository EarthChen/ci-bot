# Unify writable paths under a single data root

The self-heal bot configured four independent writable-path environment variables — `CIHEAL_WORK_ROOT`, `CIHEAL_BARE_ROOT`, `CIHEAL_AUDIT_DIR`, `CIHEAL_LOG_DIR` — whose defaults collided with each other and with `CIHEAL_BOT_ROOT` (a read-only resource root). That produced redundant `.env` entries, inconsistent defaults (`tmpdir()` in code vs `<BOT_ROOT>/.ci-data/` in the example), and writable data mixed into the read-only resource root. We replace the four variables with one required `CIHEAL_DATA_ROOT`; `work/`, `bare/`, `audit/`, and `logs/` derive from it as sub-directories. Bare clones and audit traces are cleaned passively by a retention policy (`config/retention-policy.json`); logs rotate via `pino-roll`. The old variables are dropped with no backward compatibility because retaining them would re-introduce exactly the redundancy this change removes.

## Consequences

Operators configure one writable path (`CIHEAL_DATA_ROOT`) instead of four, and `CIHEAL_BOT_ROOT` / `CIHEAL_PI_BASE_DIR` stay as the read-only resource root and credential root respectively. Retention thresholds (bare max age + entry cap, audit max age, log size + keep count) live in `config/retention-policy.json` (bot-owned, non-sensitive) rather than as environment variables, keeping the variable count down. Existing deployments that set the removed variables must update `.env` and relocate any retained bare clones / audit traces into the new data root. Cleanup is passive (runs inside the normal clone / write paths), so no timer or long-lived sweeper process is introduced.
