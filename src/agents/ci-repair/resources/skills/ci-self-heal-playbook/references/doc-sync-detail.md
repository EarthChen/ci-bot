# 文档同步详表 — G2 时机 + 只动相关段落

本文档是 `ci-self-heal-playbook` 的层 3 详尽参考，按需 Read。

## 何时同步

**仅 class 2 触发文档同步**（被测代码行为变更导致测试过时）。

| class | 文档同步 |
|---|---|
| 1 | 否（测试 bug，被测代码没变，文档无需动） |
| 2 | 是（被测代码行为变更，文档可能需跟上） |
| 3 | 否（补测试，未改被测代码行为） |
| 4/5 | 否（转交，无修复） |

## 同步范围（铁律）

**只改与变更行为直接相关的段落**。具体：

- API 描述段（方法签名、用途说明）。
- 参数语义段（参数含义、取值）。
- 返回值说明段（返回类型、含义、可能的异常）。
- 行为示例段（调用示例、输出示例）。

**禁止**：
- 全文重写文档。
- 改格式、排版、标题层级。
- 动无关段落（如改动 `add()` 但去改 `subtract()` 的文档）。
- 补全新文档（spec 未要求的文档不补）。

## 判定"相关段落"

1. 从 MR diff 找被测代码改了哪个方法/类的哪个行为。
2. 在 `docs/` 或 `*.md`（README 中的 API 段落）搜索该方法名/行为描述。
3. 只改命中且与变更行为直接相关的段落。
4. 若无相关文档 → 跳过（不同步，不补新）。

## 示例

**class 2 场景**：`Calculator.add(int, int)` 改为返回 `Optional<Integer>`（MR diff），测试过时。

- 找文档：`docs/calculator.md` 含 `add(int, int): int` 描述。
- 改：`add(int, int): int` → `add(int, int): Optional<Integer>`，并更新"返回值"段说明 Optional 语义。
- 不改：`subtract`、`multiply` 的文档段（未变更）。
- 不动：文档排版、标题。

**反模式**：
- ❌ 顺手重构整篇 `calculator.md` → 越界。
- ❌ 给 `add` 加 3 段最佳实践说明 → 越界（不是同步变更，是补新内容）。
- ❌ 改 README 的"安装"段 → 无关段落。

## 输出

文档改动与测试修复一并通过 bash 应用到工作区（git add/commit），bot 代码从 `git diff` 提取真实 patch。你只需在 `summary` 里描述改了什么，不需要在结构化结果里放文件内容。

若 class 2 但无相关文档 → patch 只含测试文件，summary 注明“无相关文档需同步”。
